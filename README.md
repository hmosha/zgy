# Подготовка данных датчиков

Задача работы — подготовить показания датчиков для модели, которая будет предсказывать аварию устройства. В исходной таблице 10 000 строк и 6 столбцов. Каждая строка описывает одно наблюдение. Столбец `fail` содержит ответ для будущей модели: 1 означает, что произошла авария, 0 — что аварии не было.

[Тетрадь с решением и графиками](sensors/Проба-решение.ipynb) · [Исходные данные](sensors/sensors.csv)

## 1. Находим и заполняем пропуски

Сначала считаем пропуски в каждом столбце с помощью `df.isna().sum()`. Для числовых столбцов используем медиану — значение в середине упорядоченного ряда. Несколько очень больших показаний слабо влияют на неё. Для текстового режима вводим отдельную метку, чтобы сохранить строки с неизвестным режимом.

| Столбец | Пропущено | Чем заполнили |
| --- | ---: | --- |
| `t_c` — температура в °C | 200 (2 %) | Медианой 36,5 °C |
| `t_f` — та же температура в °F | 200 (2 %) | Медианой 97,7 °F |
| `mode` — режим работы | 100 (1 %) | Словом «неизвестно» |

## 2. Удаляем дубликат строки

Метод `duplicated()` нашёл одну строку, которая полностью повторяла предыдущую запись. С помощью `drop_duplicates()` удаляем лишнюю копию. Остаётся **9 999 наблюдений**.

## 3. Разбираем выбросы

Гистограмма показывает, где сосредоточено большинство показаний. Диаграмма размаха помогает заметить удалённые от основной группы значения. Решение о том, что с ними делать, зависит от смысла измерения.

- **Температура.** Основная группа лежит в пределах 34–39 °C, следующее значение — 44,2 °C. Для учебной обработки выбираем границу 40 °C (104 °F). Выше неё оказались 11 наблюдений. Строку с ошибочным измерением можно удалить целиком, но тогда потеряются и режим, и отметка об аварии. Поэтому в тетради сохраняем строки и заменяем только температуры медианами. Все 11 наблюдений отмечены как аварии, поэтому перед такой заменой в реальной задаче стоило бы проверить, мог ли датчик зафиксировать перегрев.
- **Часы с последнего обслуживания (`hours`).** Устройство действительно может долго работать без обслуживания. Если больших значений много и они допустимы, можно сохранить их и сжать шкалу. В тетради применяем `np.log1p(hours)`, то есть вычисляем натуральный логарифм от `1 + hours`. Например, 1 000 часов превращаются примерно в 6,91. Порядок наблюдений сохраняется.

## 4. Проверяем повторяющиеся значения

Здесь смотрим, насколько разнообразны значения **внутри одного столбца**. Метод `nunique()` считает разные значения, а `value_counts()` показывает, как часто встречается каждое. Так можно найти постоянные и почти постоянные признаки.

У версии прошивки `fw` два значения. После удаления дубликата версия `v1` встречается в 9 969 строках (99,7 %), а `v2` — в 30 (0,3 %). Для этого задания исключаем почти постоянный `fw` из признаков для обучения.

## 5. Удаляем лишние признаки

Температуру записали дважды: в градусах Цельсия (`t_c`) и Фаренгейта (`t_f`). Из одной шкалы всегда можно получить другую по формуле `t_f = 1.8 * t_c + 32`. Корреляция между столбцами равна 1. Оставляем `t_c`, чтобы хранить одно измерение один раз. Версию прошивки убираем по результатам предыдущего шага.

```python
df = df.drop(columns=["t_f", "fw"])
```

## 6. Кодируем режим и проверяем результат

С помощью `pd.get_dummies` превращаем `mode` в три столбца: `mode_boost`, `mode_normal` и `mode_неизвестно`. Для каждой строки единица стоит у её режима, в двух остальных столбцах стоят нули.

**Итог — 9 999 строк, 6 столбцов, 0 пропусков.** Пять столбцов можно использовать как входные признаки: температура, преобразованное время и три признака режима. Шестой столбец `fail` — целевая метка. Работа заканчивается проверкой подготовленной таблицы.

## Как запустить

Открой `Проба-решение.ipynb` в Jupyter из папки `sensors`, где рядом лежит `sensors.csv`. Понадобятся Python, pandas, NumPy и Matplotlib версии 3.10 или новее. Выбери **Run → Run All Cells**. Тетрадь заново прочитает CSV и выполнит все шаги по порядку.
